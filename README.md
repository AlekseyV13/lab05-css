# Практична робота №11–12: Взаємодія Front-end із сервером. REST API та CRUD-операції

Цей проєкт є багатосторінковим каталогом, який демонструє повноцінну взаємодію клієнтського JavaScript із сервером через REST API. Дані більше не є статичними — вони отримуються, створюються, оновлюються та видаляються асинхронно.

## 🚀 Реалізований функціонал (CRUD-операції)

У проєкті реалізовано повноцінний цикл роботи з даними за допомогою `fetch()` та `async/await`:

- **C (Create) - POST-запит:** На сторінці `item-form.html` реалізовано форму для додавання нових курсів/проєктів. Дані валідуються перед відправкою, після чого створюється новий запис у базі даних.
- **R (Read) - GET-запити:** - Отримання колекції всіх записів для сторінки каталогу з відображенням станів (loading, error, empty).
  - Отримання одного запису (`GET /items/:id`) для попереднього заповнення форми при редагуванні.
- **U (Update) - PATCH-запит:** Сторінка форми вміє працювати в режимі редагування. Якщо в URL передано `?id=...`, форма завантажує існуючі дані, а після зміни відправляє `PATCH`-запит для їх оновлення.
- **D (Delete) - DELETE-запит:** У каталозі реалізовано видалення карток із попереднім підтвердженням дії (confirm). Інтерфейс автоматично оновлюється без перезавантаження сторінки.

## ✨ Додаткові фічі
- **API-шар:** Усі HTTP-запити винесені в окремий модуль `js/api.js` для чистоти коду.
- **Фільтрація та сортування:** Реалізовано пошук за назвою, фільтрацію за категоріями та сортування за ціною/рейтингом.
- **Пагінація:** Механіка "Показати ще", що підвантажує наступну порцію карток.
- **Локальне сховище:** Збереження улюблених карток (Favorites) у `localStorage`.
- **Модальні вікна:** Реалізовано модальне вікно для перегляду детальної інформації про курс.
